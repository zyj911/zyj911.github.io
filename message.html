本页已接入全站统一的导航、页脚、搜索与响应式栅格。下方为需求文档中约定的功能清单， 按顺序实现即可直接并入站点，无需改动公共样式。

已完成（骨架部分）

  • 页头与全站导航已接入
  • 留言、心愿入口已进入全站搜索索引
  • 表单基础样式（输入框 / 按钮 / 提示）可复用
  • 移动端布局断点已统一

待开发（本模块核心）

  • 注册 / 登录：密码加密存储（bcrypt），前端做实时校验
  • 心愿留言：富文本编辑（加粗、插图），提交后进入待审核状态
  • 审核展示：仅通过审核的留言上墙，支持分页或滚动加载
  • 举报与回复：用户可举报不当内容，管理员后台处理
  • 接口：POST /api/messages、GET /api/messages?status=approved
  • 数据持久化：MySQL messages 表 + 用户表外键关联

协作约定

接口与开发规范

1

接口先定契约

与 C 成员先敲定字段：id / userId / content / status / createdAt / likes。前端按契约写 mock，后端按契约实现，联调只对字段不对人。

2

审核是产品逻辑

默认 status = pending，只有 approved 才渲染。管理员操作记录保留操作人与时间，便于答辩时讲“内容治理”。

3

降级方案

后端未就绪时，留言先落 localStorage 并标注“本地演示”，保证答辩现场可完整走通流程。
